# メモリンバー（Memorimber）


> **何もなかった、なんてことはない。**

メモリンバーは、高校生活の日常にある小さな出来事を「写真1枚＋一言」で残し、思い出の木やクイズを通して自分の経験を思い出すためのスマートフォン向けWebアプリです。サービス名は「メモリー（Memory）」と「リメンバー（Remember）」を組み合わせています。

毎日日記を書くのではなく、友達との帰り道、放課後の教室、学校行事、何気ない会話など、「残しておきたい」と思った日に短時間で記録することを大切にしています。

## 想定するユーザー

地元の高校に通い、生徒会活動や学校行事、部活動などさまざまな経験をしている高校3年生を主なユーザーとして想定しています。普段から写真を撮り、友人と昔の写真を見ながら当時の出来事を話す一方で、夜に一人でいるときなど、ふと「高校生活で何もしていない」と焦りや寂しさを感じることがあります。

## 解決したい課題

ユーザーには思い出がないのではありません。写真を見れば高校生活の出来事を思い出せるものの、日々の忙しさや大量の写真の中に経験が埋もれ、「自分の思い出」として認識し、振り返る機会が少ないことが課題です。

そこで、毎日の日記や後からの写真整理を求めるのではなく、何かあった日に写真1枚と一言だけを記録し、楽しみながら繰り返し振り返れる体験を提供します。「何もしていない」と感じたときに、行事だけでなく、放課後の寄り道や友達との会話といった小さな出来事にも気付き、自分が過ごしてきた日々を実感できることを目指します。

## 体験の流れ

**残す → 育つ → 思い出す → 言葉として残る**

- 写真と一言で、その日の出来事を残す
- 記録するたびに、思い出の木へ花が咲き、古い花が実へ育つ
- 実を収穫し、思い出の一部分から答えるクイズで当時を思い出す
- クイズの後に実へ具体的な名前を付け、目に見える場所へ残す
- 記録を月ごとのアルバムにまとめ、Webや印刷で振り返る

### 思い出の木

ホームには、投稿した思い出が育っていく「思い出の木」を表示します。構想では、一つの思い出につき一つの花が咲き、新しい記録が増えると古い花から実へ変化します。現在の実装は体験を確認するための見た目を中心とした段階ですが、UIデータは次の3状態を独立して扱える構造にしています。

1. 写真を投稿すると、小さな実が `growing`（成長中）になり、`growth` で成長度を持つ
2. 一定まで育つと `quiz-ready`（クイズ可能）になり、実を押してクイズへ進める
3. クイズを終えると `harvested`（収穫済み）になり、自分で付けた単語が木の上へ漂う

木の画像、押せる実、収穫後の単語は別レイヤーです。今後データベースや成長条件を追加しても、木の画像を作り直さずに各思い出の状態を差し替えられます。

収穫済みの単語は、長押しして掴んだ後、ホーム画面内の好きな位置へ移動できます。文字の濃さは固定値ではなく、その時点の表示位置から木までの距離に応じて変化します。一定速度以上で縦横に振るか、くるくる回して12回分の動きを加えると関連する思い出を表示し、移動した配置は別画面へ移るまでの一時状態として扱います。現在はサンプルの関連付けですが、各単語が `relatedMemoryIds` を複数持てるため、将来は投稿内容やタグから抽出した関連思い出へ差し替えられます。

クイズは、写真を拡大・ぼかし・モザイク加工した状態から出来事を当てるものや、一言から写真を選ぶものなど、思い出の一部分を手がかりにすることを想定しています。最初から記録のすべてを見せず、自分から思い出そうとすることで、周辺の出来事や当時の気持ちまで振り返り、思い出への愛着を深められる体験を目指します。

ヘッダーのメニューから設定画面を開けます。アクセントカラー、BGM音量、効果音音量は共通の設定状態として保存されています。`NEXT_PUBLIC_BGM_URL` に音源を設定すると、BGMは画面をまたいでループ再生され、設定のBGM音量へ常に追従します。音量を0にすると無音になります。

プロフィールでは、写真付きアイコン、ニックネーム、写真枚数を経験値にした最大20のレベル、過去の活動統計から表示する記録を扱います。レベル10以降は累計写真枚数とクイズ・収穫・共有などの追加条件を両方満たしたときに上がり、条件待ちの間に追加した写真も累計へ繰り越します。追加条件は直前のレベルへ到達した時点の活動値を基準に、その後の増加分だけで判定できる構造です。レベル要件・到達時点の基準値・記録定義はUIから分離しており、将来データベース上の実績値へ差し替えられます。

ページ遷移や画像読み込みなどの処理中は、各画面左上の芽アイコンと `Memorimber` が穏やかに点滅します。処理が完了すると通常表示へ戻り、異常時に表示が残り続けないよう安全停止時間も設けています。

## この解決策が効果的な理由

想定ユーザーは、高校3年間にしたことを尋ねられれば答えられ、写真を見ながら友人と話しているときには「何もしていない」と感じません。このことから、必要なのは新しい経験を増やすことではなく、すでにある経験を思い出すきっかけだと考えています。

写真は過去の出来事を思い出す手がかりになりますが、受験期に毎日日記を書いたり、大量の写真を後から整理したりすることは負担になります。記録を「写真1枚＋一言」に絞り、木が育つゲーム性を加えることで、手軽さと続ける楽しさを両立します。さらに、記録が増えるほど月間アルバムとクイズが充実するため、未来の自分が振り返るために今日を残す動機にもつなげます。

## 既存サービスとの違い

一般的な写真・アルバムサービスが写真の整理、共有、フォトブック作成を主な目的とするのに対し、メモリンバーは、在学中から何気ない日常を繰り返し思い出す機会を作ることを目的としています。

文化祭や修学旅行のような大きな行事だけでなく、放課後の教室、帰り道、友達と食べたものなど、学校の卒業アルバムには残りにくい出来事を「自分から見た高校生活」として残します。記録を花や実として育て、クイズで能動的に思い出し、「放課後のアイス」のような具体的な名前を実へ付けて目に見える形で残すことが、本サービス独自の体験です。

## データについて

Supabase接続時の投稿は、ログイン中ユーザーの非公開Storage `memory-images` と `memories` テーブルへ永続保存します。アルバム・詳細画面はDBから取得するため、ページを再読み込みしても投稿が残ります。React Contextは表示用キャッシュで、保存先ではありません。

写真はJPEG・PNG・WebP・HEIC・HEIF（20MB以下）に対応し、元ファイルを変換せず保存します。HEIC・HEIFはブラウザによってプレビューできないため、表示できない場合は案内を出します。画像URLは公開URLではなく、有効期限付きの署名URLです。

画像アップロード後にDB登録が失敗した場合は、今回アップロードした画像だけを削除します。通信切断などで結果が不明な場合は保存済み画像の誤削除を避け、画面の「保存状態を確認・後片付け」から再確認できます。同じタブ内の再読み込みに備え、処理ID・ユーザーID・画像パスだけを `sessionStorage` に記録します（写真・本文・認証情報は記録しません）。

Supabase未設定時のローカル開発ではサンプルを閲覧できますが、新しい投稿はできません。木・クイズは引き続きサンプルによるプロトタイプで、今回の保存処理とは未連携です。「デモデータを初期化」は実データを削除しません。

実装内容と実環境での確認手順は [思い出保存の引き継ぎ](docs/issue-34-save-memories.md) を参照してください。

Supabaseには、ユーザーごとの思い出を保存する `memories` テーブルと、非公開の `memory-images` Storageバケットを作成するmigrationがあります。RLSにより本人のレコードと画像だけを操作できる設計ですが、現在の投稿UIとはまだ接続していません。

## 認証について

ログイン・新規登録・ログアウト、Cookieセッションの更新、未ログイン時のページ保護、本人の `profiles` 読み取りまでを実装しています。`profiles` のINSERT・DELETEはフロントから行わず、登録時の行作成はDB側Triggerへ任せます。

Supabaseの接続情報が未設定の場合、ローカル開発では既存UIを確認できるようページ保護を一時的に通過させ、ログインフォームは無効表示になります。本番環境では設定不足のまま保護ページを公開しません。

メール確認の有無やメールテンプレートなど、Supabaseプロジェクト側の設定に依存する部分は実プロジェクト接続後に確認が必要です。

### Supabase Dashboard の認証設定

1. **Authentication > URL Configuration** の Site URL に本番URL（例: `https://your-app.vercel.app`）を設定します。
2. 同画面の Redirect URLs に本番の `https://your-app.vercel.app/auth/callback` と、ローカル確認用の `http://localhost:3000/auth/callback` を追加します。Preview Deploymentでもメール確認を行う場合は、そのURLも許可します。
3. **Authentication > Providers > Email** でEmailプロバイダーを有効にし、Confirm emailの利用有無を確認します。
4. **Project Settings > API / Connect** からProject URLとPublishable Keyを取得します。`service_role`、secret key、Database PasswordはこのアプリやVercelへ登録しません。

Vercelとローカルの `.env.local` には、どちらも次の公開情報を登録します。旧形式のプロジェクトでPublishable Keyが発行されていない場合だけ、`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` の代わりに `NEXT_PUBLIC_SUPABASE_ANON_KEY` を利用できます。

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
```

接続後は、新規登録、確認メールのcallback、ログイン、保護ページへの遷移、`/api/profile` の本人プロフィール応答、ログアウト、ログアウト後の保護ページからのリダイレクトを順に確認してください。ブラウザの開発者ツールではSupabaseの認証Cookieが作成・更新されることと、クライアントへ配信されたコードやVercelの環境変数に秘密鍵が含まれないことも確認します。

## 開発・実行手順

### 1. 必要な環境を用意する

以下をインストールしてください。

- Node.js 22.19.0
- npm（Node.jsと一緒にインストールされます）
- Git

このプロジェクトではNode.jsのバージョンを `22.19.0` に固定しています。nvmを使用している場合は、リポジトリ直下で次のコマンドを実行すると `.nvmrc` に指定されたバージョンへ切り替えられます。

```bash
nvm use
```

ターミナルまたはPowerShellを開き、バージョンを確認します。

```bash
node --version
npm --version
git --version
```

`node --version` の結果が `v22.19.0` になっていれば準備完了です。このプロジェクトではNode.js 22.19.0とnpm 10で動作確認しています。

### 2. リポジトリを取得する

まだリポジトリを取得していない場合は、次のコマンドを実行します。

```bash
git clone https://github.com/Rgh-33/Memorimber.git
cd Memorimber
```

すでに取得済みの場合は、ターミナルでこのリポジトリのフォルダへ移動してください。

### 3. 依存パッケージをインストールする

リポジトリ直下で次のコマンドを実行します。

```bash
npm install
```

`node_modules` フォルダが作成され、Next.js、React、Tailwind CSSなど、実行に必要なパッケージがインストールされます。初回は数分かかる場合があります。

Supabaseへ接続する場合は `.env.example` を参考に `.env.local` を作成し、プロジェクトの公開URLと公開キーを設定します。`service_role` やsecret keyは設定しないでください。

```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_xxx
```

### 4. 開発サーバーを起動する

```bash
npm run dev
```

起動に成功すると、ターミナルに次のようなURLが表示されます。

```text
Local: http://localhost:3000
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開くと、メモリンバーを閲覧できます。

開発サーバーを停止するときは、起動したターミナルで `Ctrl + C` を押してください。

### 5. ポート3000が使用中の場合

別のアプリがポート3000を使用している場合、Next.jsが自動的に3001などの別ポートを提案することがあります。ポートを明示する場合は次のように起動します。

```bash
npm run dev -- -p 3001
```

その場合は [http://localhost:3001](http://localhost:3001) を開いてください。

### 6. コードを検査する

ESLintでコードを検査します。

```bash
npm run lint
```

エラーが表示されなければ、Lintは成功です。

### 7. 本番用ビルドを確認する

最適化された本番用ファイルを生成し、型やルートを含めてビルドできることを確認します。

```bash
npm run build
```

保存処理の自動テストは `npm test` で実行します。Supabaseクライアントの通信先をテスト内の模擬応答に置き換えるため、実プロジェクトへの書き込みや認証情報は必要ありません。

ビルド成功後、本番用サーバーを起動できます。

```bash
npm run start
```

ブラウザで [http://localhost:3000](http://localhost:3000) を開いてください。終了するときは `Ctrl + C` を押します。

本番用サーバーを別ポートで起動する場合は、次のように実行します。

```bash
npm run start -- -p 3001
```

### 8. 写真が表示されない場合

サンプル写真は外部URLから読み込むため、表示にはインターネット接続が必要です。ネットワークやフィルタリング設定によって読み込めない場合でも、写真選択エリアからローカル画像を選択して投稿プレビューを確認できます。

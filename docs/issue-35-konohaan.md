# issue-35: 葉・花・実の成長プレビュー

対象ブランチ: `feature/issue-35-konohaan`。既存の他ブランチから独立した作業ツリーで実装する。

## 試し方

1. このブランチの作業ツリーで `npm run dev -- --port 3035` を実行し、ホームを開く。
2. 木の下の「プレビュー」をオンにする（Supabase未設定時は最初からオン）。
3. 「1枚アップロード」を押す。最初の1枚は芽になり、7枚で木が育つ。
4. 7枚目で最初の写真の実が完成する。実をタップして、その写真のクイズに答える。
5. 答えを確認したら「一言を残す」に単語を入れ、チェックボタンで収穫する。
6. 木に戻ると、その単語が花びらに載る。長押しして動かし、振る／回すと関連する写真を表示する。キーボードのEnterでも写真を開ける。
7. 日付入力・「1日進める」・左右の月移動で月替わりを確認する。日付だけでは実は成長しない。

## 成長

同じ月に成功したアップロードを古い順に並べる。1枚追加するごとに、すでにある各写真が1段階ずつ進み、新しい写真は葉から始まる。7段階で停止し、古い写真から順に収穫可能になる。

1. 葉
2. 小さなつぼみ
3. 大きなつぼみ
4. 綺麗な花
5. やや枯れた花と綺麗な花
6. 枯れる直前の花・綺麗な花・下に小さな実
7. 枯れた花・綺麗な花・下に完成した実

成長の基準は撮影日ではなくDBの `created_at`。日付を過去にして投稿してもアップロード順は変わらない。既存のサンプルに限り、アップロード日時がないため写真の日付を使う。

木は月単位で分かれ、その月の1〜7枚で大きくなる。新しい月は空から始まり、月ごとに枝の向きと葉の色も変わる。前月の木・未収穫の実は前月の記録に残る。過去の収穫済み花びらは翌月にも表示される。

重なりを防ぐため、木は12枚ずつ、花びらは6枚ずつ表示する。超過した場合のみ矢印で切り替える。新しい説明文・成長メッセージは追加せず、見出しやナビゲーションを維持している。風と花びらのアニメーションは `prefers-reduced-motion` に対応。

## データと検証範囲

- プレビューのアップロードは既存のサンプル写真を用いたシミュレーション。実際のアップロード、DB変更、アルバム件数の変更は行わない。
- プレビューと収穫単語は、この試作ではアカウント別の `sessionStorage` に保存する。同じタブのページ移動・再読み込みで復元されるが、タブを閉じた後や別端末への同期は対象外。写真自体の既存の永続保存処理は維持する。
- 初期化はプレビューだけを消す。実際の写真や実際の木の収穫記録を消さない。
- 答えを確認した後に収穫できる。未回答・未成熟の実、空の単語、同じ実の重複収穫は防ぐ。単語は12文字以内。
- `npm test`: 成長順、日付だけでは成長しないこと、月末・年末・うるう年、収穫条件、写真との紐付け、翌月の花びら保持、および既存の保存処理を確認。
- `npm run lint`、TypeScriptチェック、`npm run build` を実行。
- SVGを静的に描画して木と成長段階を確認。ブラウザーのエラーページが操作ポリシーでブロックされたため、実ブラウザーでのタップ・振る操作、モバイルのレイアウト、実際のSupabase接続は未検証。

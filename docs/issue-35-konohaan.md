# issue-35: 葉・花・実の成長プレビュー

対象ブランチ: `feature/issue-35-konohaan`。普段の `memorimber` フォルダーで作業する。

## 試し方

1. このブランチの普段のフォルダーで `npm run dev` を実行し、`http://localhost:3000` を開く。
2. 木の下の「プレビュー」をオンにする（Supabase未設定時は最初からオン）。
3. 「1枚アップロード」を押す。最初の1枚は芽になり、7枚で木が育つ。
4. 最初の写真の後に7枚追加する（合計8枚）。最初の写真の実が完成し、タップするとその写真だけの1問を開く。
5. 答えを確認すると、写真の下・入力欄の上に正解／不正解と、その写真の日付・思い出の文章が表示される。不正解の場合は正しい答えも表示する。操作は入力欄とチェックだけで、薄文字の「写ってるもの」を目印に単語を入れ、チェックで収穫する。
6. 目の前の花びらに鉛筆で文字が書かれ、風に舞い上がる。空を見上げる動きに続き、ライトでは黒、ダークでは白にフェードし、一拍置いて木へ戻る。戻った木にその花びらが浮く。長押しして動かし、振る／回すと関連する写真を表示する。キーボードのEnterでも写真を開ける。
7. 日付入力・「1日進める」・左右の月移動で月替わりを確認する。日付だけでは実は成長しない。

開発サーバーの生成先は `.next-konohaan-dev`、本番ビルドの生成先は `.next`。ビルドや別プレビューの生成ファイルが混ざり、CSS・JavaScriptが404になるのを防ぐ。ブランチを切り替えた際は開発サーバーも再起動する。

表示が見出しだけになっていた3000番ポートで、修正後にCSS・JavaScriptすべての200応答と、8枚のプレビュー追加による木・実の表示を確認済み。

ログインは `.env.local` のある普段のフォルダーから起動した3000番を使う。3035番の検証用コピーは接続情報を持たないため、実アカウントのログインには使わない。認証先への通信が許可された端末で `npm run dev` を実行する。実行環境の通信制限による `EACCES` は、メールアドレス・パスワードの誤りではない。

ログイン失敗時は、通信・メール確認未完了・試行回数制限・サーバー障害・資格情報不一致を区別し、再試行でも元の移動先を保持する。公開設定APIの200応答と、架空の確認用入力に対して実際の認証処理から資格情報不一致が返ることを確認済み。実ユーザーのパスワード入力とログイン成功は本人による再確認が必要。認証やRLSを無効化する変更は行っていない。

## 成長

同じ月に成功したアップロードを古い順に並べる。各写真は自分の葉から始まり、その後の追加アップロードで成長する。自分自身のアップロードは成長回数に含めず、追加7枚で収穫可能になる。見た目は以下の7段階で、追加5〜6枚時点は小さな実、追加7枚で完成した実になる。木全体が育つ枚数（合計7枚）と、個々の写真が収穫可能になる条件（その写真の後に7枚）は別。

1. 葉
2. 明るい色の小さなつぼみ
3. 膨らんだ大きなつぼみ
4. 一輪の明るい花が開く
5. 同じ花の花弁が下がり、中央の子房が膨らみ始める
6. 花が落ちた後の小さな実
7. 花がなくなり、収穫できる完成した実

成長の基準は撮影日ではなくDBの `created_at`。日付を過去にして投稿してもアップロード順は変わらない。既存のサンプルに限り、アップロード日時がないため写真の日付を使う。

木は1か月に1本だけで、その月の1〜7枚で大きくなる。同じ月の追加アップロードでは別の木を作らず、同じ木の上で葉・花・実が生え変わる。新しい月は空から始まり、月ごとに枝の向きと葉の色も変わる。前月の木・未収穫の実は前月の記録に残る。過去の収穫済み花びらは翌月にも表示される。

木や枝のページ切り替えは設けない。実を押しやすい12か所だけを使い、収穫した場所に、待っている最も古い写真の葉・花・実が入る。他の写真の位置は詰め直さない。満杯の間に追加した写真も成長と収穫可能な状態を保持し、空きができた順に木へ出る。写真の全件データと表示位置は分け、表示待ちの写真もクイズ画面から参照できる。位置はアカウント別・月別・実データ／プレビュー別に保存し、ページ移動や再読み込みで保つ。旧形式の保存データも写真や単語を消さずに読み込む。

収穫した単語はページ分けや件数制限をせず、新しいものからすべて同じページに表示する。花びらは文字数に応じた幅のまま横に詰め、画面幅に合わせて折り返す。単語が増えるとその領域が伸びて木が下へ移動し、入りきらない単語と木はページのスクロールで見られる。文字を小さくして押し込まず、揺れの余白と44px以上の操作範囲を保つ。新しい説明文・成長メッセージは追加せず、見出しやナビゲーションを維持している。風と花びらのアニメーションは `prefers-reduced-motion` に対応。

木はRPGの環境アートを意識した、奥行きのある描画。ねじれた幹に樹皮の溝・陰影・苔・根の張りをつけ、先端に向かって細くなる枝を重ねる。葉は前後の層に分け、細かな葉の輪郭・折り返しの光・落ちる影で茂みの厚みを出す。葉の形は毎回同じ計算で生成し、写真を追加してもちらつかない。幹と葉を小さく別々に揺らす。最初の1枚だけは独立した芽として描く。成長段階と実の写真ID、収穫・振る・回す操作は維持する。

2枚目への成長では、根元と茎を保ったまま、左右の同じ節から双葉が開く。小さな木への切り替えや木質の枝は2枚目では表示せず、茎が少し伸びながら2枚目の葉をほどく。3〜6枚目は完成木の縮小表示にせず、細い幹が上へ伸び、中心から外側へ枝分かれし、葉の塊が少しずつ広がる苗木・若木として描く。7枚目で従来の完成形になり、それ以降は写真の枚数によって木や枝を増やさない。固定した枝の先で写真ごとの葉・花・実だけが育つ。実の高さは少しずつずらし、押しやすい間隔を確保する。月ごとに左右を反転する際も、幹・枝・葉・実を同じ座標系で描く。

6段階目で実が付き始めた時点から花は表示しない。完成した実は写真ごとに、ル・レクチェ、りんご、パンノキ、ドラゴンフルーツ、ヤトロファ・クルカス、にっこり梨からランダムに選ぶ。指定に合わせて、候補内ではりんごが選ばれる比率を高くしている。ページ移動や再読み込みのたびに種類がちらつかないよう、同じ写真IDには同じランダム結果を使う。洋梨の縦長の輪郭、りんごのくぼみ、パンノキの網目、ドラゴンフルーツの苞、ヤトロファ・クルカスの分かれた果皮、にっこり梨の大きな丸みと斑点をSVGで描き分ける。実の傾きと大きさも写真ごとに変え、枝ごとに左右位置と垂れ下がる長さをずらす。

アップロードのたびに、直近に追加された写真の枝先だけへ明るい金色の光が渦を巻いて集まり、放射状にきらめいてから葉が現れる。1・2枚目も芽と双葉の位置で同じ金色の演出を行う。増えず、収穫可能にもならず一段階だけ育った既存写真には、小さな淡い光が静かに瞬く演出を使う。そのアップロードで初めて小さな実になった写真には焦点光を残し、他の成長結果から見つけやすくする。収穫可能になった写真は全体の成長結果より一拍遅れて拡大し、二重の光輪と放射光を出す。その後も、完成した実には明るい脈動光と小さなきらめきを残す。`prefers-reduced-motion` では渦と拡大を表示せず、成長後の形と静止した強調だけを表示する。

綺麗な花と収穫した花びらは、既存のスタイルカラーに連動する。ライトでは淡い地色に濃い文字、ダークでは深い地色に明るい文字を使う。待機中の文字は薄くせず、振る操作中だけ従来の消えていく演出を残す。

木の輪郭は根元を固定したまま高さを6%増やし、横幅を2%抑えて微調整。実のタップ位置にも同じ変形を適用する。収穫単語の花びらはこの変形の対象外で、スタイル色・読みやすい文字色・浮遊・振る／回す操作を保つ。

上部に葉の束を5つ足し、既存の幹・枝・輪郭を保ちながら横長の印象を整えた。花びらは細長く不揃いな縁、浅い切れ込み、細い筋と繊維を持つ共通SVG。丸い光沢や輪郭線をなくし、スタイル色に植物の落ち着いた色を混ぜている。目の前の収穫演出と木の画面の浮遊で同じ花びらを使う。

浮遊する文字は14pxの太字と不透明な墨色／クリーム色。文字数に合わせて花びらの幅と高さを変え、4文字なら84×約47px、12文字なら114×66pxに収める。7文字以上は2行とし、文字の外側の余白を抑える。小さい花びらでも操作範囲の高さは44px以上。画面幅に応じて横に並べ、空きがなくなったら下の行へ続ける。収穫時の文字も太く大きくし、鉛筆の移動幅を合わせた。舞い上がり・視点移動・白黒のフェードの順序と時間は変更していない。

収穫演出は約5〜6秒。文字の書き込み、花びらの遠ざかりと空への視点移動、白／黒のフェード、短い静止、木への復帰を順に実行する。チェック時点で単語を保存し、ページ移動をまたぐProviderで演出を保持する。連打は1回にまとめ、演出中は背後の操作を止める。Escapeで舞い上がる部分を短縮でき、動きを減らす設定では短いフェードだけになる。新しい操作ボタンや説明文は追加しない。

## データと検証範囲

- プレビューのアップロードは既存のサンプル写真を用いたシミュレーション。実際のアップロード、DB変更、アルバム件数の変更は行わない。
- プレビューと収穫単語は、この試作ではアカウント別の `sessionStorage` に保存する。同じタブのページ移動・再読み込みで復元されるが、タブを閉じた後や別端末への同期は対象外。写真自体の既存の永続保存処理は維持する。
- 初期化はプレビューだけを消す。実際の写真や実際の木の収穫記録を消さない。
- 答えを確認した後に収穫できる。未回答・未成熟の実、空の単語、同じ実の重複収穫は防ぐ。単語は12文字以内。
- 実のリンクにはその写真のIDだけを渡す。クイズは必ず `QUESTION 1 / 1` で、回答・単語入力・収穫後は木に戻る。「次の問題」や別の写真への自動移行はない。IDが無効・未成熟・収穫済みなら他の写真やサンプル問題に置き換えない。

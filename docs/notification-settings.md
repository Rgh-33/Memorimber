# 端末ごとの通知設定

設定 → 通知（`/settings/notifications`）から、この端末の通知の有効化・無効化、収穫／過去の思い出の種類、受信曜日を設定できます。旧 `/settings/more` は専用ページに転送します。

- 初期設定は両方の種類がON、毎日。曜日は日本時間です。
- 種類と曜日は「保存する」で反映。両種類OFF、または曜日なしの場合、自動通知を送りません。
- 定期実行は既存の `0 11 * * *`。現在のHobbyプランでは日本時間20:00〜20:59の間に実行されます。
- 選んだ曜日に端末ごとに1種類を送ります。収穫可能な実、または1〜3年前の同じ時期・前後7日の思い出があれば優先し、対象がない日は思い出の木を開く案内を送ります。毎日受け取る場合は全曜日を選択してください。
- 無効化・失効後に登録し直す場合、種類と曜日は初期設定に戻ります。ログアウトは現在の端末の購読とログインセッションだけを解除します。
- 設定画面の「有効」は端末の購読がDBに登録済みという意味です。OSでの通知表示を保証しません。

## 必要なDB・環境設定

必要なマイグレーションは `20260911000000` → `20260918000000_device_notification_settings.sql` → `20260919000000_daily_memory_reminders.sql` の順です。今回の追加は最後の1本で、端末別履歴に `daily` 種別を許可します。適用済みファイルは変更していません。DBへの適用はユーザーが行います。

`20260918000000` は購読の種類・曜日、新しい端末単位の配信履歴、テスト送信の回数制限用テーブルとRPCを追加します。既存購読は両種類ON・毎日になります。履歴・回数制限はservice_roleのみ操作できます。

配信には以下の環境変数が必要です。公開鍵はビルド時にフロントへ埋め込まれるので、変更した場合は再ビルドが必要です。

- `NEXT_PUBLIC_VAPID_PUBLIC_KEY`
- `VAPID_PRIVATE_KEY`（公開鍵と同じペア）
- `VAPID_SUBJECT`（連絡先のmailtoまたはHTTPS URL）
- `SUPABASE_SECRET_KEY`
- `CRON_SECRET`（自動通知用。VercelでTypeをSecret、適用先をProductionに設定。既存値があれば変更せず利用）

導入は新マイグレーション適用 → 環境変数確認 → デプロイの順です。旧配信処理との同時実行を避け、20時台以外に切り替えてください。旧ユーザー単位履歴は残し、同日の記録があれば新処理も送信を控えます。アプリを旧版へ戻す場合、新しい端末別設定を旧Cronは参照しない点に注意してください。

Vercel Cronは本番デプロイで自動実行されます。Productionにも上記の変数を設定し、Settings → Cron Jobsで `/api/cron/memory-reminders` が有効であることを確認してください。Previewの通知登録は本番とは別です。本番URLをホーム画面に追加し、そのPWAから通知を有効化してください。

## APIと送信記録

- `PATCH /api/push-subscriptions`：既存の `{ endpoint }` を受け取り、`enabled` に加えて `preferences` を返します。
- `PUT /api/push-subscriptions`：`{ endpoint, preferences: { harvest_enabled, anniversary_enabled, weekdays } }` を保存します。曜日は0=日〜6=土の重複しない整数配列です。本人の購読のみ更新できます。
- `POST /api/push-subscriptions/test`：`{ endpoint }` の本人購読だけへ固定文面を送信。成功時200、未登録404、失効410、回数制限429（Retry-Afterあり）、送信失敗502、設定・DB不備503。認証と同一オリジンの確認を行います。
- テストはユーザー単位で60秒に1回。複数端末・同時リクエストもDB側で制限し、当日の自動通知履歴は変更しません。
- 自動通知の `push_notification_deliveries` は購読ID＋日付で重複を防止します。送信前に記録する方式のため、失敗やタイムアウトでも同日中は再送しません。購読削除時は対応する履歴も削除します。
- Cronレスポンスの `sent` / `failed` / `skipped` / `empty` は従来どおりユーザー単位です。`empty` は互換性のため残し、対象なしの場合も汎用通知へ切り替えるので通常は0です。端末ごとの成否は新しい履歴テーブルで確認します。
- 汎用通知は `notification_type=daily`、`candidate_id=null` で記録され、タップ先は `/` です。曜日が対象外、両種類OFF、購読なしの場合は送信しません。手動テスト・木のプレビューには影響しません。
- Cronは `Memory reminders` のログに日本時間の日付と集計結果を記録します。設定不足・処理失敗も記録しますが、個人情報や通知本文、鍵、購読URLは含めません。
- `sent` はPushサービスが受け付けた状態です。端末で表示された証明ではありません。テスト成功も定期実行の成功を保証しません。

## 確認の分担

コードレビュー、単体テスト、lint、ビルドをエージェント側で確認します。DB適用・ブラウザ操作・実機への通知送信は行いません。

ユーザー確認では、設定の保存と再表示、2端末での種類・曜日の独立、片方のログアウト後も他方が有効なこと、iPhone PWAのテスト通知、20時台の自動配信を確認してください。テスト通知が届いて自動通知が届かない場合は、Cron実行・配信条件・当日の履歴を順に確認します。
